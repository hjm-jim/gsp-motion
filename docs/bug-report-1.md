# bug_report#1：圆半径异常和 F/B 重合

## 原因

半径绘制公式本身是正确的：圆仍使用两父点的距离作为半径。真正的问题是垂线/平行线的参数基准点与 GSP 不一致。

设锚点为 A，基准直线的定义向量为 d。GSP 的平行线定义点为 `A-d/2`、`A+d/2`；垂线先将 d 旋转为 `(-dy,dx)`，同样在锚点两侧各取一半。锚点对应线参数 t=0.5。

旧实现取 `A`、`A+d`，无限直线的形状仍相同，但 t=0 被错误解释成锚点。GSP 中落在这些线上的约束点因而偏移半个定义向量。本例四个绿色圆的圆心正是此类约束点，继而导致半径变化和交点 F 误落在 B 上；蓝色小圆也随错误交点变化。

## 修复

`geometry-core.cjs` 中垂线、平行线统一使用以锚点为中点的定义端点。点约束公式 `P=p1+t(p2-p1)`、圆的半径公式、圆圆交点分支均保留。直接由两点定义的直线/射线/线段参数不改变。

修复作用于解析和逐帧重算，不通过修改原 GSP、固定半径、强行分开标签或套用缓存坐标掩盖问题。旧兼容 JSON 在重新渲染时也会重算；推荐重新解析原 GSP 以刷新 info.md。

## 证据和验证

静态分析目标仍是 GSP5.03 Build1014RK，解包 PE 的 SHA-256 为 `42ff86f7d1e6fd43bfd75327b14427d0b2d081c79dcc2aea01b1d9fbaad20957`。

- 原始机器码 `0x4B4790`（垂线）、`0x4B4850`（平行线），以及 `0x410F60` 的向量缓存写入，确认两端以锚点为中心。
- 用已安装的 Unicorn 在隔离内存中执行以上算术指令，覆盖普通、斜线和竖直基线，6 组端点均与修复公式一致；在缓存更新调用前停止，没有启动或控制桌面程序。
- 独立执行原始 `0x444EC0` 圆圆求交例程：修复后的 F/G/H/E 与 CLI 最大差约 `1.61e-13`，圆半径残差最大 `8.53e-14`；现有交点分支正确，无需更改。重放隔离了 CRT errno 访问，并将正数平方根包装映射为 FSQRT/RET；几何例程字节未改。
- 原生反编译接口未能返回该函数，本次证据使用文件字节反汇编和受控算术重放；不将静态分析描述为实际操作原程序所得。

回归样例为 `examples/bug_report#1.gsp`。`test-line-basis.cjs` 检查定义端点、四个绿色圆半径、F/B 分离、四交点共小圆，以及 A 在 −8°..+8° 单向运动时父圆与交点的逐帧残差和名称避让；还验证旧 JSON 缓存被重算、普通直线参数保持原语义。

此修复用于 CLI 的几何核心和离线动画预览；随后按用户确认，同步到独立的旧网格查看器 `产出/gsp5-viewer/dist/app.js`，保留原网格、配色与交互。用浏览器文件输入实际读取 bug_report#1 和 12 份已有 GSP 样例，点坐标、圆心和半径均与 CLI 一致，页面无运行错误。已打开的旧页面需刷新或重新打开，再读入 GSP。
