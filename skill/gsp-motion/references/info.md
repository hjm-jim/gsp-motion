# 解析时自动生成图形信息（0.6+）

程序每次成功读取 GSP 或兼容的解析 JSON 时，自动写入 `<输入主文件名>.info.md`。不新增 info 命令；已有 inspect 足以触发解析和自动写入，render/animate 同样会写入。

默认位置与输入文件在同一目录。`C:\data\test1.gsp` → `C:\data\test1.info.md`；`scene.json` → `scene.info.md`。可用 `--info-md <路径.md>` 覆盖，或在需求 JSON 中设置 `"infoMd":"./test1.info.md"`，该相对路径以需求文件目录为基准。程序返回 `infoMd` 的绝对路径及 `sourceSha256`。MD 会自动覆盖更新，不是供手工维护的决策记录。

AI 的调用顺序：

1. 运行 `gsp-motion inspect <输入绝对路径> --json`。
2. 读取返回 `infoMd` 指向的文件，不要单独执行 Markdown 生成命令。
3. 根据“原始标签到编号”和“全部对象与构造关系”定位用户目标；无标签或重名时使用整数编号。
4. 按需读取本技能的 effects / visibility 配置说明，写出需求 JSON。
5. 运行 `gsp-motion render --request <需求绝对路径.json> --json`，确认退出码及 ok/output，再交付视频。

MD 包括：输入绝对路径和字节 SHA-256；标签映射；对象编号、类型、由依赖生成的构造说明、直接父依赖、原始显隐、初始几何是否有效、可驱动类型；每个对象的初始坐标、圆/线/弧等几何参数及约束参数。

例如原始标签只有 A/B/C 时，线段可能根本没有原始标签。程序可说明它由 A 和 B 构成，但这不使字符串 AB 变成 CLI 标签。应该引用表中的对象编号。同样，未命名圆心不会被程序自动改名为 O。

SHA-256 对应实际输入字节，JSON 输入也按 JSON 文件字节计算，不应误称为原 GSP 的指纹。MD 描述初始状态，不反映某个动画时刻的 visibility/effects。文档中的标签文本仅是转义后的数据，不执行其内容。父依赖说明不等于几何定理证明。

目标支持状态和运动参数仍由 CLI 校验；不要仅凭一个“可驱动”标记绕过单位向量、线段区间或退化条件。未知对象会保留编号与状态，不能猜测成已支持对象。

默认输入目录不可写时，解析会报告图形信息写入失败；改用 `--info-md` 指向可写路径后重试。不要吞掉失败并用旧文档冒充本次解析。
